# 项目开发规则

> **创建日期**: 2026-03-08  
> **目的**: 统一项目开发规范，提高代码质量和可维护性

---

## 核心原则

### 1. DRY 原则 (Don't Repeat Yourself)

**定义**: 不要重复自己 - 每一个知识点在系统中都应该有一个单一、明确、权威的表示。

**应用场景**:

#### ✅ 常量管理
- 所有常量（如活动类型、状态码等）应集中在 `lib/constants/` 目录下管理
- 其他地方只引用，不重复定义

**示例**:
```dart
// ✅ 正确做法
// lib/constants/event_constants.dart
class EventConstants {
  static const List<String> eventTypes = [
    '观影团',
    '影评征集',
    '线上观影',
    // ...
  ];
}

// 其他文件中使用
import '../../constants/event_constants.dart';
// 使用 EventConstants.eventTypes

// ❌ 错误做法
// 在多个文件中重复定义
final List<String> _eventTypes = ['观影团', '影评征集', ...];
```

#### ✅ 工具函数
- 重复使用的函数应提取到 `lib/utils/` 目录
- 避免在多个文件中复制粘贴相同的代码

#### ✅ UI 组件
- 重复使用的 UI 组件应提取到 `lib/widgets/` 目录
- 通过参数配置实现不同的展示效果

#### ✅ 样式和主题
- 所有颜色、字体、间距等应在 `lib/app_theme.dart` 中统一定义
- 避免在代码中硬编码颜色值

## 代码组织规范

### 目录结构

```
lib/
├── constants/        # 常量定义
│   └── event_constants.dart
├── config/          # 配置文件
│   └── api_config.dart
├── models/          # 数据模型
├── services/        # 服务层（API、存储等）
├── pages/           # 页面
├── widgets/         # 可复用组件
├── utils/           # 工具函数
├── app_theme.dart   # 主题配置
└── main.dart        # 入口文件
```

---

## 命名规范

### 文件命名
- 使用小写字母和下划线: `event_constants.dart`
- 类名使用大驼峰: `EventConstants`
- 变量和函数使用小驼峰: `eventTypes`

### 常量命名
- 静态常量使用小驼峰: `static const String typeViewingGroup`
- 列表常量使用复数: `eventTypes`

## 最佳实践

### 1. 单一职责原则
- 每个类、函数只做一件事
- 保持函数简短，易于理解和测试

### 2. 可维护性优先
- 优先考虑代码的可读性和可维护性
- 避免过度优化

### 3. 统一数据源
- 所有配置、常量都应有唯一的定义位置
- 修改时只需改一处

### 4. 代码复用
- 发现重复代码时，立即重构
- 提取公共逻辑到独立的函数或类

## 实践案例

### 案例1：活动卡片组件重构

**问题**：`index_events_tab.dart` 和 `activities_page.dart` 中有重复的活动卡片组件代码。

**解决方案**：
1. 创建通用组件 `lib/widgets/event_card_common.dart`
2. 创建工具类 `lib/utils/event_filter_utils.dart` 统一筛选逻辑
3. 创建筛选栏组件 `lib/widgets/event_filter_bar.dart`
4. 两个页面都引用这些通用组件

**效果**：
- 代码量减少约 60%
- 修改一处，所有地方生效
- 逻辑统一，减少 bug
