# 动态点赞功能问题说明

## 问题描述

### 错误信息
```
I/flutter (10012): 点赞动态请求: http://10.0.2.2:7070/api/feeds/1/like
I/flutter (10012): 点赞动态响应状态码: 200
I/flutter (10012): 点赞动态响应内容: {"code":500,"message":"服务器内部错误：could not execute statement [Field 'feed_id' doesn't have a default value] [insert into likes (created_at,target_id,target_type,user_id) values (?,?,?,?)]; SQL [insert into likes (created_at,target_id,target_type,user_id) values (?,?,?,?)]; constraint [feed_id]","data":null}
```

### 问题分析

1. **HTTP状态码**: 200 (成功)
2. **业务状态码**: 500 (服务器内部错误)
3. **错误原因**: 数据库插入失败 - `feed_id` 字段没有默认值

### 根本原因

后端在插入点赞记录到 `likes` 表时，SQL语句中缺少 `feed_id` 字段：

```sql
-- 当前的SQL（错误）
insert into likes (created_at,target_id,target_type,user_id) values (?,?,?,?)

-- 应该是（正确）
insert into likes (created_at,target_id,target_type,user_id,feed_id) values (?,?,?,?,?)
```

## 数据库设计问题

### likes 表结构问题

根据错误信息，`likes` 表的设计存在以下问题：

1. **字段冗余**: 同时存在 `target_id`、`target_type` 和 `feed_id`
   - `target_id` + `target_type`: 通用的目标标识（可以是动态或评论）
   - `feed_id`: 专门的动态ID字段

2. **字段约束不合理**: `feed_id` 字段设置为 NOT NULL 但没有默认值
   - 如果 `feed_id` 是必填的，为什么还需要 `target_id` + `target_type`？
   - 如果使用通用设计，`feed_id` 应该是可空的

### 建议的数据库设计

#### 方案1: 通用设计（推荐）

```sql
CREATE TABLE likes (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    target_type VARCHAR(20) NOT NULL,  -- 'FEED' 或 'COMMENT'
    target_id BIGINT NOT NULL,         -- 动态ID或评论ID
    created_at TIMESTAMP NOT NULL,
    UNIQUE KEY uk_user_target (user_id, target_type, target_id)
);
```

#### 方案2: 分离设计

```sql
-- 动态点赞表
CREATE TABLE feed_likes (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    feed_id BIGINT NOT NULL,
    created_at TIMESTAMP NOT NULL,
    UNIQUE KEY uk_user_feed (user_id, feed_id)
);

-- 评论点赞表
CREATE TABLE comment_likes (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    comment_id BIGINT NOT NULL,
    created_at TIMESTAMP NOT NULL,
    UNIQUE KEY uk_user_comment (user_id, comment_id)
);
```

## 后端修复方案

### 临时修复（快速）

在插入点赞记录时，根据 `target_type` 设置 `feed_id`：

```java

    like.setFeedId(targetId);  // 设置 feed_id

```

### 长期修复（推荐）

1. **修改数据库表结构**
   - 将 `feed_id` 字段改为可空: `ALTER TABLE likes MODIFY feed_id BIGINT NULL;`
   - 或者删除 `feed_id` 字段，只使用 `target_id` + `target_type`

2. **统一点赞逻辑**
   - 使用 `target_type` + `target_id` 作为通用标识
   - 移除 `feed_id` 字段的依赖

## 前端临时处理方案

在后端修复之前，前端可以添加更友好的错误提示：

```dart
/// 点赞动态
Future<ApiResponse<LikeResponse>> likeFeed(int feedId) async {
  try {
    final url = Uri.parse('$baseUrl/api/feeds/$feedId/like');
    final headers = await getAuthHeaders();
    
    debugPrint('点赞动态请求: $url');

    final response = await http.post(url, headers: headers);

    debugPrint('点赞动态响应状态码: ${response.statusCode}');
    debugPrint('点赞动态响应内容: ${response.body}');

    final jsonResponse = jsonDecode(response.body) as Map<String, dynamic>;
    
    // 检查业务错误码
    if (jsonResponse['code'] == 500) {
      return ApiResponse<LikeResponse>(
        code: 500,
        message: '点赞功能暂时不可用，请稍后再试',
        data: null,
      );
    }
    
    return ApiResponse<LikeResponse>.fromJson(
      jsonResponse,
      (data) => LikeResponse.fromJson(data as Map<String, dynamic>),
    );
  } catch (e) {
    debugPrint('点赞动态失败: $e');
    return ApiResponse<LikeResponse>(
      code: -1,
      message: '网络请求失败: $e',
      data: null,
    );
  }
}
```
