# 创建收藏夹功能修复

> **修复日期**: 2026-03-04  
> **问题**: 创建收藏夹时类型转换错误

---

## 🐛 问题描述

### 错误信息
```
type 'Null' is not a subtype of type 'int' in type cast
```

### 前端日志
```
创建收藏夹请求: http://10.0.2.2:7070/api/collections
请求体: {name: test, type: MOVIE, description: 火影忍者, isPublic: false}
创建收藏夹响应状态码: 200
创建收藏夹响应内容: {"id":1,"userId":1,"name":"test","description":"火影忍者","type":"MOVIE","isSystem":false,"isPublic":false,"coverImage":null,"itemCount":0,"createdAt":"2026-03-04T18:42:47.0886026","updatedAt":"2026-03-04T18:42:47.0886026"}
创建收藏夹失败: type 'Null' is not a subtype of type 'int' in type cast
```

### 后端日志
```sql
INSERT INTO collections
(cover_image, created_at, description, is_public, is_system, item_count, name, type, updated_at, user_id)
VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)
```

---

## 🔍 问题分析

### 1. 数据格式不匹配
后端直接返回 Collection 对象：
```json
{
  "id": 1,
  "userId": 1,
  "name": "test",
  "description": "火影忍者",
  "type": "MOVIE",
  "isSystem": false,
  "isPublic": false,
  "coverImage": null,
  "itemCount": 0,
  "createdAt": "2026-03-04T18:42:47.0886026",
  "updatedAt": "2026-03-04T18:42:47.0886026"
}
```

前端期望的是 ApiResponse 格式：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "id": 1,
    "userId": 1,
    ...
  }
}
```

### 2. 字段解析问题
`itemCount` 字段在某些情况下可能为 null，导致类型转换失败。

---

## ✅ 修复方案

### 1. 修复 Collection 模型
使 `itemCount` 字段更加健壮，支持 null 值：

```dart
factory Collection.fromJson(Map<String, dynamic> json) {
  return Collection(
    id: json['id'] as int,
    userId: json['userId'] as int,
    name: json['name'] as String,
    description: json['description'] as String?,
    type: json['type'] as String,
    isSystem: json['isSystem'] as bool,
    isPublic: json['isPublic'] as bool,
    coverImage: json['coverImage'] as String?,
    itemCount: (json['itemCount'] as num?)?.toInt() ?? 0,  // 修复：支持null
    createdAt: json['createdAt'] as String,
    updatedAt: json['updatedAt'] as String,
  );
}
```

### 2. 修复 createCollection 方法
兼容两种响应格式：

```dart
static Future<ApiResponse<Collection>> createCollection({...}) async {
  try {
    // ... 发送请求 ...

    final jsonResponse = jsonDecode(response.body);
    
    if (jsonResponse is Map<String, dynamic>) {
      // 检查是否是ApiResponse格式（有code字段）
      if (jsonResponse.containsKey('code')) {
        // 标准ApiResponse格式
        return ApiResponse<Collection>.fromJson(
          jsonResponse,
          (data) => Collection.fromJson(data as Map<String, dynamic>),
        );
      } else {
        // 直接返回Collection对象
        final collection = Collection.fromJson(jsonResponse);
        return ApiResponse<Collection>(
          code: 200,
          message: 'success',
          data: collection,
        );
      }
    } else {
      throw Exception('未知的响应格式');
    }
  } catch (e) {
    // ... 错误处理 ...
  }
}
```

## 💡 经验总结

### 1. 前后端数据格式统一的重要性
- 建议后端统一使用 ApiResponse 格式包装所有响应
- 或者前端统一处理多种格式（当前方案）

### 2. 健壮的数据解析
- 使用 `as num?` 而不是 `as int` 来处理数字类型
- 使用 `?.toInt() ?? 0` 提供默认值
- 避免直接类型转换导致的崩溃

### 3. 响应格式检测
- 使用 `containsKey('code')` 判断是否为 ApiResponse 格式
- 根据不同格式采用不同的解析策略

### 4. 调试技巧
- 打印完整的响应内容
- 分析错误堆栈定位问题字段
- 逐步验证每个字段的解析
